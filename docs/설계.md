# SideDesk 설계

컴퓨터 옆에 세워 둔 폰에 컴퓨터 상태를 보여 주고, 폰에서 컴퓨터를 조작하는 프로그램이다.
PhoneBox 의 코드와 파일은 가져오지 않는다. 이 폴더에서 전부 새로 짠다.

## 1. 정해진 것

| 항목 | 결정 |
|---|---|
| 컴퓨터 프로그램 | Rust. 맥과 윈도우를 처음부터 함께 |
| 안드로이드 앱 | Kotlin |
| iOS 앱 | Swift |
| 기능 | 홈(시계, 날씨), AI 세션, 성능, 프로세스, 단축키, 음악, AOD |
| 화면 | 코드는 전부 새로. 3안 디자인을 이어갈지는 확인 필요(9번) |

## 2. 전체 구조

```
[컴퓨터]  Rust 프로그램 하나 (맥, 윈도우 공통)
  트레이와 설정 창
  수집기 ─> 상태 보관소 ─> 구독 관리 ─┐
  실행기 <────────────────────────────┤
                                      │ 암호화된 연결 하나
            USB / 블루투스(맥)         │
[폰]                                  │
  공용 코어 (Rust, 두 앱이 같이 씀) ───┘
     ├─ 안드로이드 화면 (Kotlin, Jetpack Compose)
     └─ iOS 화면 (Swift, SwiftUI)
```

- 암호화, 통신 규칙, 재연결은 공용 코어에 한 번만 짠다. 컴퓨터와 두 앱이 같은 코드를 쓴다.
- 화면, 진동, 밝기처럼 폰마다 다른 것만 Kotlin 과 Swift 로 짠다.
- 웹 화면(WebView)은 쓰지 않는다.

## 3. 폴더

```
core/       통신 규칙, 암호화, 재연결 (Rust)
desktop/
  app/      시작점, 트레이, 설정 창
  domain/   상태, 구독, 명령 (운영체제를 모름)
  mac/      맥 전용 수집과 실행
  windows/  윈도우 전용 수집과 실행
android/    Kotlin
ios/        Swift
docs/
```

`domain` 은 `mac` 과 `windows` 를 모른다. 운영체제별 코드는 정해진 인터페이스만 채운다.

## 4. 연결

컴퓨터가 폰에 접속한다. 안드로이드와 iOS 를 같은 방향으로 맞추기 위해서다.

| 길 | 안드로이드 | iOS | 맥 | 윈도우 |
|---|---|---|---|---|
| USB | adb forward | usbmux | 됨 | 안드로이드는 adb, iOS 는 애플 드라이버 필요 |
| 블루투스 | BLE L2CAP | BLE L2CAP | 됨 | 쓸 수 있는 공식 방법을 아직 못 찾음 |

- 처음 한 번 짝을 맺는다. 양쪽에 같은 숫자를 띄워 확인하고 서로의 공개 키를 저장한다.
- 이후에는 저장한 키로만 연결한다. 폰의 다른 앱이 포트에 붙어도 키가 없으면 끊긴다.
- 암호화는 Noise 방식(`snow` 라이브러리)을 쓴다.
- 컴퓨터에는 포트를 열지 않는다. 설정 창도 웹 서버 없이 띄운다.
- 케이블을 꽂으면 USB 로, 빼면 블루투스로 옮긴다. 옮기는 동안 화면은 마지막 값을 유지한다.

## 5. 데이터

- 폰이 "지금 보이는 것"을 알리면, 컴퓨터는 그것만 모아서 보낸다.
- 아무도 안 보는 수집기는 멈춘다. 폰이 안 붙어 있으면 전부 멈춘다.
- 처음에 한 번 전체를 보내고, 그다음은 바뀐 값만 보낸다.
- 메시지 형식은 Protobuf 하나로 정한다. 버전이 다르면 모르는 값은 무시한다.

| 자료 | 주기 |
|---|---|
| 성능 | 보일 때 1초, 작은 칸일 때 2초 |
| 프로세스 | 큰 화면 2초, 작은 칸 6초 |
| 음악, 볼륨 | 바뀔 때 |
| AI 세션 | 파일이 바뀔 때 |
| GitHub, GitLab | 3분 |
| 날씨 | 15분 |

## 6. 명령과 보안

- 폰은 등록된 단축키의 번호만 보낸다. 명령 문장은 보낼 수 없다.
- 프로세스 종료는 폰에서 한 번 더 확인하고, 컴퓨터는 번호와 시작 시각이 모두 맞을 때만 끝낸다.
- 날씨 인증키는 키체인(맥)과 자격 증명 관리자(윈도우)에 둔다. 배포 파일에는 넣지 않는다.
- 인터넷은 기상청만 나간다. GitHub, GitLab 은 설치된 `gh`, `glab` 을 실행해 받는다.

## 7. 폰마다 다른 점

| | 안드로이드 | iOS |
|---|---|---|
| 화면 안 꺼짐 | 됨 | 앱이 앞에 떠 있을 때만 |
| AOD(검은 화면) | 앱 안에서 | 앱 안에서 |
| 진동 | 세기 조절 | Core Haptics 로 세기 조절 |
| 접는 폰 | 접고 펼 때 배치 다시 계산 | 해당 없음 |
| 설치 | APK | 애플 개발자 계정 필요. 무료 계정은 7일마다 다시 설치 |

## 8. 경계 상황

| 상황 | 동작 |
|---|---|
| 연결이 끊김 | 마지막 값을 흐리게 보이고 아이콘을 지운다. 0.5초부터 간격을 늘려 최대 10초마다 다시 시도 |
| 컴퓨터가 잠들었다 깸 | 연결을 새로 맺고 전체 상태를 다시 보낸다 |
| 보내는 속도를 폰이 못 따라감 | 쌓지 않고 최신 값만 남긴다. 알림과 명령 결과는 버리지 않는다 |
| 명령을 보낸 직후 끊김 | 명령마다 번호를 붙여, 다시 보내도 두 번 실행하지 않는다 |
| 폰 여러 대 | 각자 따로 구독한다. 수집은 한 번만 한다 |
| 수집기 하나가 멈춤 | 그 수집기만 다시 켠다. 다른 화면은 그대로 |
| 앱과 컴퓨터 버전이 다름 | 큰 버전이 다르면 연결하지 않고 업데이트하라고 알린다 |
| 설정 파일이 깨짐 | 직전 정상본으로 되돌리고 알린다. 저장은 임시 파일에 쓴 뒤 바꿔치기한다 |

## 9. 목표와 확인

PhoneBox 에서 잰 값은 2026-11-25 사용 중 값이다. 같은 조건에서 새 프로그램과 다시 비교한다.

| | PhoneBox | 목표 |
|---|---|---|
| 컴퓨터 메모리 | 약 266MB | 60MB 아래 |
| 컴퓨터 CPU (코어 하나 기준) | 16시간 평균 약 7%, 사용 중 14~15% | 사용 중 2% 아래 |
| 폰 메모리 | 약 180MB | 120MB 아래 |

확인이 필요한 것
- 화면 디자인: 3안을 이어갈지, 시안부터 다시 할지
- 완료 알림: 세션이 10초 넘게 쉴 때만 "끝남"으로 볼지
- iOS: 애플 개발자 계정과 시험할 아이폰이 있는지
- 윈도우: 시험할 PC 가 있는지

## 10. 순서

| 단계 | 내용 | 끝난 기준 |
|---|---|---|
| 1 | 공용 코어, 짝 맺기, USB | 맥과 안드로이드가 키로 붙고, 뽑았다 꽂아도 다시 붙는다 |
| 2 | 맥 수집기와 실행기 | 여섯 기능의 값이 나오고 CPU, 메모리 목표를 지킨다 |
| 3 | 안드로이드 화면 | 여섯 화면, AOD, 진동이 폰에서 돈다 |
| 4 | 블루투스(맥) | 케이블을 빼도 이어진다 |
| 5 | 윈도우 | 깃허브 윈도우 서버에서 빌드와 자동 시험이 통과한다 |
| 6 | iOS | 시뮬레이터에서 화면이 돌고, 실제 폰은 기기가 있으면 확인한다 |
| 7 | 배포 | 인증키와 개인 설정이 배포 파일에 없는지 검사한 뒤 묶는다 |

1단계부터 윈도우에서 컴파일되는지 함께 검사한다. 블루투스와 iOS 의 실제 동작은 해당 단계에서 확인한다.
새 앱은 앱 ID 가 달라서 지금 쓰는 PhoneBox 와 같이 깔린다. 다 될 때까지 PhoneBox 는 그대로 둔다.
