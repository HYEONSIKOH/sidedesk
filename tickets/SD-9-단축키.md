# SD-9 [공통] 단축키

| 종류 | 상태 | 우선순위 | 라벨 |
|---|---|---|---|
| 작업 | 진행 중 | 높음 | Core, Desktop, Android |

## 목적

컴퓨터 설정 창에서 등록한 버튼을 폰에 띄우고, 폰에서 누르면 컴퓨터가 그 일을 한다(앱 열기, 파일과 폴더 열기, 주소 열기, 키 조합, 시스템 동작). 폰은 등록된 단축키의 번호만 보내고 명령 문장은 보낼 수 없다(설계 6절).

## 범위

이번에 하는 것은 맥(컴퓨터)과 안드로이드다. 윈도우 실행기는 SD-8 머지 뒤 같은 포트를 채워 붙이고(그 전까지 "지원하지 않음"), iOS 화면은 iOS 트랙에서 한다.

등록(맥, 윈도우 설정 창)
- 설정 창에 "단축키" 칸을 더한다. 더하기, 고치기, 지우기, 순서 바꾸기
- 종류 다섯
  | 종류 | 등록할 때 고르는 것 | 맥 | 윈도우 |
  |---|---|---|---|
  | 앱 열기 | 설치된 앱 목록에서 고르기 | `.app` 묶음 ID 로 저장, NSWorkspace 로 연다 | 실행 파일 경로 또는 스토어 앱 AUMID 로 저장, `ShellExecuteExW` 로 연다 |
  | 파일, 폴더 열기 | 운영체제 파일 고르기 창 | 경로 저장, NSWorkspace 로 기본 앱에서 연다(폴더는 Finder) | 경로 저장, `ShellExecuteExW("open")`(폴더는 탐색기) |
  | 주소 열기 | 주소 입력 | 기본 브라우저 | 기본 브라우저 |
  | 키 조합 | 누른 키를 그대로 받아 적기 | `CGEventPost`(손쉬운 사용 권한 필요) | `SendInput` |
  | 시스템 동작 | 정해진 목록에서 고르기 | 아래 표 | 아래 표 |
- 시스템 동작(시안의 볼륨, 방해 금지, 잠금)
  | 동작 | 맥 | 윈도우 |
  |---|---|---|
  | 소리 끄기/켜기(상태를 버튼에 보임) | CoreAudio 기본 출력 장치의 음소거 속성 | `IAudioEndpointVolume::SetMute` |
  | 화면 잠금 | 애플의 잠금 단축키 Ctrl+Cmd+Q(macOS 10.13 이상)를 키 조합과 같은 길(`CGEventPost`)로 보낸다. 손쉬운 사용 권한 필요. 보낸 키로 실제 잠기는지는 검색으로 확인 못 해 구현 때 맥에서 먼저 본다 | `LockWorkStation`(공개 API, user32). 돌려받는 값은 "잠그기 시작함"이고 잠겼는지는 아니다 |
  | 방해 금지 | 집중 모드를 켜고 끄는 공개 API 는 없다. 사람이 단축어 앱에서 "집중 모드 설정" 동작으로 켜기, 끄기 단축어를 만들어 두면 `shortcuts run "<이름>"` 으로 부른다. 설정 창에서 두 단축어 이름을 고른다 | 공개 API 없음(알려진 방법은 비공식 레지스트리, CloudStore 값). 이번에는 지원하지 않음 |
- 이름(폰 버튼 아래 글자, 생략 가능)과 아이콘, 색을 고른다

아이콘
- 시안처럼 색 바탕 위 한 색 그림이다. 앱 자체의 아이콘을 뽑아 보내지 않는다(보낼 크기와 저작권 문제를 피하고, 두 운영체제에서 같은 모양)
- 그림은 정해진 묶음에서 고른다: 터미널, 폴더, 코드, 브라우저, 계산기, 설정, 활동, 음악, 볼륨, 방해 금지, 잠금 + 몇 개(파일, 별, 번개 등). 그림 묶음은 안드로이드, iOS, 설정 창이 같은 이름표를 쓰고 그림은 각자 그린다
- 색은 시안 색 묶음에서 고른다. 앱을 고르면 그림과 색을 짐작해 미리 채운다(터미널 앱 → 터미널 그림)

폰(안드로이드, iOS)
- 단축키 큰 화면과 작은 칸(앞 네 개)은 시안(docs/images/screens 넷째 그림) 그대로
- 누르면 진동 한 번, 결과는 실패할 때만 짧은 알림 문장으로

통신
- 컴퓨터는 단축키 목록(번호, 이름, 그림 이름표, 색, 켜짐 상태)을 구독한 폰에 보낸다. 목록이나 상태가 바뀔 때만 다시 보낸다
- 폰은 `실행(단축키 번호, 명령 번호)` 만 보낸다. 명령 번호로 두 번 실행을 막는다(지금 프로세스 종료와 같은 규칙)
- 단축키 번호는 등록 때 정한 바뀌지 않는 번호다(자리 순서가 아님). 순서를 바꾸거나 지운 뒤 늦게 온 명령이 다른 일을 하지 않는다

하지 않는 것
- 셸 명령 실행(의문점 후보, 아래)
- 여러 단계를 묶은 매크로, 조건 실행
- 폰에서 단축키 등록, 고치기
- 음악 재생 조작과 볼륨 크기 조절(음악 티켓). 여기서는 소리 끄기/켜기만

## 보안

- 컴퓨터는 등록된 번호만 실행한다. 모르는 번호, 지워진 번호는 "없는 단축키" 로 거절
- 등록 내용(경로, 주소, 키)은 폰에 보내지 않는다. 폰은 이름, 그림, 색만 안다
- 주소 열기는 `http`, `https` 만 받는다(`file:`, 사용자 정의 프로토콜로 다른 앱을 부르는 것을 막음)
- 파일 열기는 등록한 경로 그대로 연다. 실행 파일(`.exe`, `.bat`, `.command`, `.sh`, `.app` 아닌 실행 비트 파일)은 "앱 열기"로만 등록하게 한다
- 키 조합은 그 순간 앞에 있는 창에 간다. 등록 창에 "앞에 있는 창에 보냅니다" 를 적는다
- 단축키 설정은 설정 폴더의 파일에 두고 임시 파일에 쓴 뒤 바꿔치기한다(지금 설정 파일과 같은 규칙)

## 경계 상황

| 상황 | 동작 |
|---|---|
| 앱이 지워짐, 파일이 옮겨짐 | 실행 때 "찾지 못함" 을 폰에 알림. 설정 창 그 줄에도 표시 |
| 명령 직후 끊김, 다시 보냄 | 명령 번호가 같으면 다시 실행하지 않는다 |
| 같은 버튼을 빠르게 여러 번 | 명령 번호가 다르면 각각 실행(앱 열기는 운영체제가 이미 뜬 앱을 앞으로 가져온다) |
| 실행이 오래 걸림(느린 앱 시작) | 실행은 따로 스레드에서. 수집과 다른 명령을 막지 않는다. 결과는 5초 안에 못 받으면 "보냈음" 으로 끝 |
| 맥 손쉬운 사용 권한 없음 | 키 조합만 실패, 설정 창에 권한 안내. 다른 종류는 그대로 |
| 윈도우 관리자 권한 창이 앞에 있음 | `SendInput` 이 막힌다(UIPI). "이 창에는 키를 보낼 수 없습니다" |
| 맥 방해 금지 단축어가 없거나 이름이 바뀜 | `shortcuts run` 실패를 "단축어를 찾지 못함" 으로 알림. 켜짐 상태는 우리가 마지막으로 바꾼 값만 안다(사람이 직접 바꾸면 모름) |
| 화면이 잠겨 있음 | 키 조합은 보내지 않고 실패로 알림. 앱, 파일 열기는 운영체제에 맡김(잠금 풀면 보임) |
| 키 조합 도중 실패 | 누른 키는 반드시 뗀다(누름만 남지 않게) |
| 소리 장치가 바뀜(이어폰 꽂음) | 기본 출력 장치를 매번 다시 찾고, 상태를 다시 보낸다 |
| 설정 파일이 깨짐 | 직전 정상본으로 되돌리고 설정 창에 알림(설계 8절) |
| 폰 여러 대 | 목록은 같은 것을 각자 받는다. 실행은 누가 보내든 한 번씩 |

## 조치

- 메시지(목록, 실행, 결과)는 공용 코어 Protobuf 에 더한다. 모르는 값은 무시
- 단축키 보관과 번호 확인, 명령 번호 중복 막기는 `desktop/domain`, 실제 실행은 운영체제 포트(`Launcher` 같은 이름)로 `desktop/mac`, `desktop/windows` 가 채운다
- 설정 창은 `desktop/window` 에 칸 하나, 앱 목록과 파일 고르기는 운영체제 포트로
- 안드로이드는 Jetpack Compose, iOS 는 SwiftUI, 둘 다 시안 그대로

## 끝난 기준

- [ ] 설정 창에서 다섯 종류를 등록하고 고치고 지우고 순서를 바꿀 수 있다(맥. 윈도우는 SD-8 뒤)
- [ ] 폰 단축키 화면과 작은 칸이 시안대로 나오고, 누르면 맥에서 그 일이 일어난다
- [ ] 지운 단축키 번호, 같은 명령 번호를 다시 보내면 실행되지 않는다(시험)
- [ ] 주소 열기는 http, https 외에는 등록과 실행 모두 거절된다(시험)
- [ ] 소리 끄기 버튼이 상태를 보이고, 컴퓨터에서 직접 바꿔도 폰 버튼이 따라 바뀐다
- [ ] 맥 손쉬운 사용 권한이 없으면 키 조합만 실패하고 설정 창에 안내가 나온다
- [ ] 윈도우용 컴파일 검사를 통과한다(실행기는 "지원하지 않음" 자리. 윈도우 실행기와 CI 시험은 SD-8 뒤)

## 의문점 후보 (tickets/의문점.md 22~26 으로 옮김)

1. 셸 명령 실행을 허용할지. 허용하면 등록 내용이 곧 임의 명령이 된다(폰은 번호만 보내므로 등록한 사람만 정할 수 있다). 기본값: 이번에는 안 함
2. 윈도우 방해 금지: 공개 API 가 없어(비공식 레지스트리, CloudStore 값뿐이고 빌드마다 바뀜) 윈도우에서는 버튼을 숨긴다. 기본값: 숨김
3. 시안의 볼륨 버튼이 노란 바탕인 것이 어떤 상태 표시인지. 기본값: 소리를 끈 상태일 때 강조
4. 아이콘을 정해진 묶음에서만 고를지, 앱 아이콘을 쓸지. 기본값: 정해진 묶음(시안 모양)

확인한 것(2026-11-27 웹 검색)
- 윈도우 `LockWorkStation`: Microsoft Learn 에 문서화된 공개 함수(winuser.h, User32). 비동기이고 성공 값은 시작만 뜻한다
- 맥 잠금: 공개 잠금 API 는 못 찾음(알려진 직접 호출은 사설 `SACLockScreenImmediate`). Ctrl+Cmd+Q 는 10.13 이상 잠금 단축키. `CGEventPost` 로 보낸 이 키가 잠그는지는 자료가 없어 구현 때 확인
- 맥 방해 금지: 단축어 앱의 "집중 모드 설정" 동작으로 만든 단축어를 `shortcuts run` 으로 부르는 방법이 쓰인다. 최신 macOS 에서 동작은 구현 때 확인
- 윈도우 방해 금지: 공식 API 없음. 커뮤니티는 레지스트리(`NOC_GLOBAL_SETTING_DND`, `QuietHoursActive`)나 CloudStore 값을 바꾸는데 빌드마다 다르고 확인된 방법이 없다
