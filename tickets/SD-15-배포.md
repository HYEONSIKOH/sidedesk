# SD-15 [공통] 배포

| 종류 | 상태 | 우선순위 | 라벨 |
|---|---|---|---|
| 작업 | 진행 중 | 높음 | Core, Desktop, Android, CI |

## 목적

설계 10절 7단계. 인증키와 개인 설정, 개인 경로가 배포 파일에 없는지 검사한 뒤 맥, 윈도우, 안드로이드 배포 파일을 묶는다. 묶은 파일은 CI 산출물로만 남기고, 공개(GitHub Release 등)는 사람이 정한다.

## 범위

컴퓨터(be)
- 맥: 릴리스 SideDesk.app 을 유니버설(arm64 + x86_64)로 묶고, 버전을 Info.plist 와 파일 이름에 넣고, .dmg 로 만든다(앱과 응용 프로그램 폴더 바로 가기)
- 맥 서명은 ad-hoc 만 한다(애플 개발자 계정 없음, 공증 없음). 처음 열 때 게이트키퍼 안내를 README 에 적는다
- 윈도우: 창 실행 파일(sidedesk.exe, 콘솔 창 없음)과 콘솔 실행 파일(sidedesk-cli.exe, pair 와 run)을 zip 으로 묶는다. win 의 SD-12 가 develop 에 들어간 뒤 맞춘다
- 배포 빌드는 모두 컴파일러의 경로 바꾸기를 써서, 빌드한 사람의 홈 경로가 실행 파일에 남지 않게 한다(지금 맥 릴리스 바이너리에 154번, 안드로이드 APK 의 core 에 12번 남아 있다)
- 비밀값 검사 스크립트: 저장소 파일과 묶은 산출물을 훑어 하나라도 나오면 실패한다. CI 에서 돈다
- CI 릴리스 작업: 맥, 윈도우, 안드로이드 배포 파일을 만들어 검사하고 actions 산출물로 올린다. Release 를 만들지 않는다

폰(fe)
- 맨 끝 "안드로이드" 절에 fe 가 쓴다

버전
- 앱(폰)과 컴퓨터 프로그램의 큰 버전이 다르면 연결하지 않고 알린다(설계 8절). 이미 있다: 연결 머리말의 큰 버전이 다르면 핸드셰이크 전에 끊고, 컴퓨터 설정 창은 그 폰 줄에 "버전이 달라 연결할 수 없습니다…"를, 폰은 "컴퓨터와 버전이 다릅니다…"를 보인다. 다시 시도하지 않는 오류로 다룬다
- 이번에는 연결 시험 하나를 더해 컴퓨터 쪽 알림까지 확인한다
- 배포 파일의 버전 표기는 저장소 버전(Cargo.toml workspace, 안드로이드 versionName)을 따른다. 연결 머리말의 큰 버전은 따로 올린다(형식이 깨지는 변경 때만)

## 비밀값 검사

찾는 것(하나라도 있으면 실패, 찾은 파일과 줄 번호와 종류만 보이고 값은 가린다)
- 개인 키 머리(`BEGIN … PRIVATE KEY`)
- 알려진 토큰 모양: GitHub(`ghp_` 등, `github_pat_`), GitLab(`glpat-`), AWS(`AKIA`), Slack(`xox?-`), Anthropic/OpenAI(`sk-ant-`, `sk-` 긴 것)
- 기상청 키 모양: 공공데이터포털 서비스 키(`serviceKey=`, `authKey=` 뒤 긴 값, 또는 끝이 `==` 인 80자 넘는 base64)
- 개인 경로: `/Users/<이름>`, `/home/<이름>`, `C:\Users\<이름>`(시험 표본의 중립 이름은 허용 목록)
- 메일 주소(허용: `noreply@anthropic.com`, `example.com` 등)
- 일련번호 모양: `serial`, `일련번호` 같은 이름표 뒤 긴 영숫자
- 실제 업무 이름과 일련번호(로컬 전용): 저장소 밖 금지어 목록 `~/.config/sidedesk/deny-words` 와 맞춰 본다. CI 에서는 하지 않는다(저장소 비밀값을 쓰지 않음). 목록이 없으면 건너뛰었다고 보인다
- 검사 도구는 열쇠고리 같은 비밀 저장소에서 값을 꺼내지 않는다. 기상청 키는 모양 규칙으로만 찾는다

훑는 곳
- 저장소에 올라간 파일 전부(`git ls-files`)
- 묶은 산출물: .app 안 파일, .dmg 를 열어 안의 파일, zip 안 파일, APK 안 파일(.so, .dex 포함)

## 끝난 기준

- 맥 .dmg, 윈도우 zip, 안드로이드 APK 가 CI 산출물로 나오고 비밀값 검사를 통과한다
- 경로 바꾸기 전 바이너리로 검사를 돌리면 실패한다(검사가 실제로 잡는지)
- 맥 .dmg 를 열어 앱이 뜨고 메뉴 막대 아이콘이 보인다(이 맥)
- README 에 맥 처음 열기 안내와 윈도우 SmartScreen 안내가 있다
- 큰 버전이 다른 폰이 붙으면 컴퓨터 설정 창에 업데이트 알림이 남는 시험이 통과한다

## 하지 않는 것

- GitHub Release 만들기, 공개, 자동 업데이트
- 애플 공증, 윈도우 코드 서명(인증서 없음)
- iOS 배포(개발자 계정 없음)

## 안드로이드

서명
- 키스토어는 저장소에 넣지 않는다. 환경변수(또는 `~/.gradle/gradle.properties`) 네 값으로 서명한다: `SIDEDESK_KEYSTORE`(파일 경로), `SIDEDESK_KEYSTORE_PASSWORD`, `SIDEDESK_KEY_ALIAS`, `SIDEDESK_KEY_PASSWORD`
- 넷이 다 있으면 그 키로 서명한 `SideDesk-<버전>.apk`
- 키가 없고 CI(`CI=true`)면 서명하지 않은 `SideDesk-<버전>-unsigned.apk`. CI 에서는 디버그 키로 대신하지 않는다(러너마다 키가 달라 덮어 설치가 안 되므로)
- 키가 없고 로컬이면 디버그 키로 서명한 `SideDesk-<버전>-debugkey.apk`(개발용)
- 빌드 로그에 "안드로이드 서명: Release|Unsigned|DebugKey" 한 줄. 비밀번호는 찍지 않는다
- 키스토어 경로가 저장소 안이면 빌드가 멈춘다. `.gitignore` 에는 이미 `*.jks`, `*.keystore` 가 있다

버전
- `versionName` 은 `Cargo.toml` 의 `[workspace.package] version` 을 gradle 이 읽는다. 버전은 한 곳에서만 바꾼다
- `versionCode` = 주 × 10000 + 부 × 100 + 수(0.1.0 → 100). 형식이 다르면 빌드가 실패한다
- APK 이름: `SideDesk-<버전>.apk`(release), `SideDesk-<버전>-measure.apk`(측정용)
- 설정 판 맨 아래에 앱 버전("SideDesk 0.1.0")을 보인다. 버전이 다르다는 안내를 받았을 때 자기 버전을 볼 곳

CI 에서 부를 작업
- `cd android && ./gradlew assembleRelease` 하나로 된다(권한 확인 `checkPermissions` 가 걸려 있다). core 는 gradle 이 `scripts/build-android.sh release` 를 불러 함께 빌드하므로 따로 부르지 않는다(경로 바꾸기 RUSTFLAGS 가 그 스크립트에 들어가면 그대로 쓰인다)
- 필요한 것: JDK 17 이상, Android SDK(platform 35, build-tools), NDK 27.2.12479018, Rust aarch64-linux-android 대상
- 산출물: `android/app/build/outputs/apk/release/SideDesk-<버전>-unsigned.apk`(CI)
- `checkPermissions`: 릴리스 합친 manifest 의 권한 일곱(블루투스 넷, 대략 위치, 진동, `<applicationId>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`)과 maxSdkVersion(블루투스 옛 둘은 30)이 정한 것과 다르면 실패한다. 라이브러리가 몰래 더한 권한을 막는다. INTERNET 은 없다

앱 모양
- 런처 아이콘: 지금은 없어 기본 아이콘이 나온다. 맥 메뉴 막대 아이콘과 같은 "둥근 네모 폰 테두리와 아래 점"을 적응형 벡터(단색 층 포함)로 만든다
- 처음 뜰 때 흰 번쩍임이 없게 창 바탕과 스플래시 바탕을 어두운 색으로 맞춘다

README 설치 줄
- 배포하는 곳에서 받은 APK 를 폰에서 열기("출처를 알 수 없는 앱" 허용) 또는 `adb install`
- 안드로이드 10 이상, arm64 폰. USB 로 쓰려면 개발자 옵션의 USB 디버깅을 켠다
