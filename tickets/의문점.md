# 의문점

사람이 정해야 하는 것만 모은다. 정하기 전까지는 "지금 한 것"대로 개발하고, 답이 나오면 고친다.

| 번호 | 무엇 | 지금 한 것 | 정할 것 |
|---|---|---|---|
| 1 | 숫자 시계 글꼴 (SD-4) | 기본 글꼴을 가장 가늘게 하고 끝이 둥근 선을 덧그려 시안과 비슷하게 맞춤 | 시안과 숫자 모양까지 같게 하려면 둥근 글꼴 파일(예: Nunito, SIL OFL)을 앱에 넣어야 함. 넣을지 |
| 2 | 설계 문서 6절 "인터넷은 기상청만" | 날씨 제공처 처음 값이 Open-Meteo 라 맞지 않음. 문서는 안 고침 | 설계 문서를 고칠지 |
| 3 | Open-Meteo 무료 조건 | 비상업 앱으로 보고 씀. 날씨 옆에 출처 링크 | 남에게 나눠 주는 무료 앱이 비상업에 드는지 info@open-meteo.com 에 물을지 |
| 4 | 휴전선 북쪽 일부를 국내로 봄 (SD-4) | 직선 경계라 개성 같은 곳은 기상청에 먼저 물음. 실패하면 Open-Meteo 로 넘어가 날씨는 나옴 | 더 정확히 할지 |
| 5 | AI 세션 "끝남" 기준 (설계 9절) | 세션이 10초 넘게 새 기록이 없고 마지막이 답이면 끝남으로 봄 | 10초가 맞는지 |
| 6 | iOS 실제 기기 (설계 9절) | 시뮬레이터에서만 확인 | 애플 개발자 계정과 시험할 아이폰이 있는지 |
| 7 | 윈도우 실제 PC (설계 9절) | 깃허브 윈도우 서버에서 빌드와 자동 시험만 | 시험할 PC 가 있는지 |
| 8 | 작업 폴더 하나 더 | iOS 와 윈도우를 기능 작업과 함께 하려고 저장소를 한 벌 더 받아(~/Desktop/project/sidedesk-b) 따로 작업. git worktree 는 아님 | 괜찮은지 |
| 9 | AI 세션 기록 파일 (SD-7) | Claude Code 와 Codex 가 컴퓨터에 남기는 기록 파일(공개 약속이 아닌 내부 모양)을 읽어 상태를 정함. 모양이 바뀌면 상태가 "알 수 없음"으로 보일 수 있음 | 이대로 갈지, 공식 훅(hook) 연동처럼 더 단단한 방법을 따로 할지 |
| 10 | 끊긴 동안의 AI 알림 (SD-7) | 끊긴 동안 생긴 끝남과 답변 대기 알림은 다시 붙어도 보내지 않음. 세션 목록에 상태로 보임 | 다시 붙으면 몇 분 안의 알림을 다시 보낼지 |
| 11 | GitLab 로그인 (SD-7) | 이 맥의 `glab` 은 로그인되지 않은 호스트가 있어 GitLab 칸은 "로그인 안 됨"으로 보일 수 있음 | 어느 GitLab 주소를 볼지 |
| 12 | 윈도우 프로세스 끝내기 (SD-8) | 강제 종료(TerminateProcess). 윈도우에는 맥처럼 정상 종료를 부탁하는 공통 신호가 없음 | 창이 있는 앱은 먼저 창 닫기(WM_CLOSE)를 보내 볼지 |
| 13 | 윈도우 블루투스 (SD-8) | 지원하지 않음. 윈도우 공개 API 에 BLE L2CAP 채널이 없음(확인한 범위) | GATT 쓰기와 알림으로 새 통로를 만들지(안드로이드, iOS 도 고쳐야 함) |
| 14 | 윈도우에서 아이폰 USB (SD-8) | 윈도우 애플 장치 서비스(TCP 27015)로 붙임. 아이튠즈나 애플 장치 앱이 깔려 있어야 함 | 실제 PC 로 확인할지(7번과 같음) |
| 15 | 윈도우 검은 창 (SD-8) | 두 번 눌러 열면 콘솔 창이 같이 뜸. 배포 때 정리 | 없음(배포 작업에서 처리) |
| 16 | 윈도우 설정 창 확인 (SD-8) | 깃허브 윈도우 서버에서 실제로 뜨는지 모름. 안 되면 컴파일 확인만 | 실제 PC 로 볼지(7번과 같음) |
| 17 | 아이폰 블루투스 알림 신호 (SD-8) | iOS 는 알림 신호에 서비스 데이터를 못 실어, 연결 번호와 지문을 GATT 특성에 두고 맥이 한 번 붙어 읽음 | 없음(기술 제약) |
| 18 | 아이폰 USB 이어받기 (SD-8) | adb 와 달리 접속한 쪽을 확인할 수 없어, 받는 순간이 아니라 짝 맺기 숫자나 키 확인 뒤에 이어받음 | 없음(기술 제약) |
| 19 | 사람이 멈춘 AI 세션 (SD-7) | Esc 로 멈추거나 Codex 를 끊은 세션은 끝남으로 보이되 알리지 않음 | 멈춤도 알릴지 |
| 20 | Claude Code 허락 창 대기 (SD-7) | 허락 창이 떠 있는 동안 기록에 남는 값을 확인 못 함. 그동안 "작업 중"으로 보이고 알림이 안 갈 수 있음 | Claude Code 공식 훅(Notification)을 SideDesk 가 설정해 정확히 잡을지 (9번과 같이) |
| 21 | GitLab 숫자 받기 (SD-7) | 로그인된 GitLab 이 없어 `glab api graphql` 의 필드(reviewRequestedMergeRequests, authoredMergeRequests, todos)를 확인 못 함. 틀리면 GitLab 칸이 "불러오지 못함"으로 보임 | 의문점 11 의 GitLab 을 정할 때 함께 확인 |
| 22 | 단축키 셸 명령 (SD-9) | 셸 명령 실행은 넣지 않음(등록 내용이 곧 임의 명령이 됨) | 넣을지 |
| 23 | 윈도우 방해 금지 (SD-9) | 공개 API 가 없어 윈도우에서는 방해 금지 단축키를 숨김 | 비공식 방법을 쓸지 |
| 24 | 시안 볼륨 버튼의 노란 바탕 (SD-9) | 소리를 끈 상태일 때 강조로 봄 | 맞는지 |
| 25 | 단축키 아이콘 (SD-9) | 정해진 그림 묶음에서만 고름(앱 자체 아이콘은 보내지 않음) | 앱 아이콘을 쓸지 |
| 26 | 맥 화면 잠금 (SD-9) | Ctrl+Cmd+Q 를 보내 잠금. 보낸 키로 실제 잠기는지는 사람이 있을 때 한 번 확인해야 함(시험 중 화면이 잠기므로 자동 시험에서 하지 않음) | 확인 결과 |
| 27 | 맥 시스템 전체 재생 정보 (SD-10) | 공개 API 가 없어 음악 앱과 Spotify 만 AppleScript 로 읽음(비공개 MediaRemote 우회는 쓰지 않음) | 다른 방법을 쓸지 |
| 28 | Spotify 앨범 그림 (SD-10) | AppleScript 가 인터넷 주소만 줘서 내려받지 않고 기본 그림 | 내려받을지(설계 6절 인터넷 규칙) |
| 29 | 윈도우 WinRT (SD-10) | 윈도우 음악은 `windows` 크레이트를 새로 들여 WinRT 로(win 이 할 때) | 들일지 |
| 30 | 맥 다른 플레이어 (SD-10) | 브라우저 등 다른 플레이어는 조작도 정보도 없음 | 미디어 키로 조작만 할지 |
| 31 | 맥 자동화 권한 창 (SD-10) | osascript 로 부를 때 권한 창이 SideDesk 이름으로 뜨는지 구현 때 확인. 서명할 때 hardened runtime 이면 `com.apple.security.automation.apple-events` 권한이 필요 | 확인 결과, 서명 방식 |
