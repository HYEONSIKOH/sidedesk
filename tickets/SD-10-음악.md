# SD-10 [공통] 음악

| 종류 | 상태 | 우선순위 | 라벨 |
|---|---|---|---|
| 작업 | 진행 중 | 보통 | Core, Desktop, Android |

## 목적

컴퓨터에서 재생 중인 곡(앨범 그림, 제목, 진행)을 폰에 띄우고, 폰에서 재생/멈춤, 이전 곡, 다음 곡, 볼륨을 조작한다. 값은 바뀔 때만 보낸다(설계 5절).

## 범위

이번에 하는 것은 맥(컴퓨터)과 안드로이드다. 윈도우 플레이어와 볼륨은 win 이 같은 포트를 채워 붙이고(그 전까지 "지원하지 않음"), iOS 화면은 iOS 트랙에서 한다.

보이는 것(시안 docs/images/screens 다섯째 그림)
- 큰 화면: 앨범 그림, "음악", 곡 제목, 진행 바와 지난 시간/전체 시간, 이전, 재생/멈춤, 다음, 볼륨 막대
- 작은 칸: 재생/멈춤 버튼, 곡 제목, 얇은 진행 줄. 작은 칸만 보일 때는 곡과 재생 상태만 보낸다(그림과 볼륨은 큰 화면일 때만, 블루투스를 아낌)
- 안드로이드와 iOS 화면은 시안 그대로

컴퓨터가 보내는 것
- 곡: 제목, 아티스트, 앨범, 전체 길이(모르면 없음), 앨범 그림(아래)
- 재생 상태: 재생 중/멈춤, 위치. 컴퓨터는 보내는 순간의 위치로 고쳐 보내고, 폰은 받은 순간의 폰 시각을 기준으로 진행 바를 스스로 움직인다(1초마다 보내지 않는다)
- 볼륨: 0~100, 음소거 여부, 조절할 수 있는지(HDMI 같은 장치는 조절 불가)
- 바뀔 때만 보낸다. 곡이 바뀌면 곡과 그림, 멈추거나 다시 재생하면 상태, 위치를 옮기면 위치

폰이 보내는 것
- 재생/멈춤, 이전, 다음, 볼륨(0~100). 명령 번호로 두 번 실행 막기(지금 규칙과 같음)

## 운영체제별 방법

맥
| 할 일 | 방법 | 비고 |
|---|---|---|
| 재생 정보 | 앱별 AppleScript(음악 앱, Spotify). 실행 중인지 먼저 보고(`NSRunningApplication`), 꺼진 앱에는 묻지 않는다(묻는 것만으로 앱이 켜진다) | 시스템 전체의 "지금 재생 중" 공개 API 는 없다. 비공개 MediaRemote 는 macOS 15.4 부터 권한 검사로 막혔다(검색 확인) |
| 바뀜 알기 | 음악 앱 `com.apple.Music.playerInfo`, Spotify `com.spotify.client.PlaybackStateChanged` 분산 알림을 구독하고, 알림이 오면 AppleScript 로 다시 읽는다 | 알림 이름은 문서화된 것이 아니다. 구현 때 지금 macOS 에서 오는지 확인 |
| 조작 | 같은 앱에 AppleScript(`playpause`, `next track`, `previous track`). 스크립트 안에서도 앱이 떠 있을 때만 말을 건다(꺼진 앱을 깨우지 않게) | 그 밖의 플레이어(브라우저 등)는 이번에 안 함 |
| 앨범 그림 | 음악 앱: `artwork 1 of current track` 의 `raw data` 를 SideDesk 캐시 폴더 파일에 쓰게 해 읽는다(원본 10MB 까지). Spotify: `artwork url` 만 준다(인터넷 주소) | Spotify 그림은 내려받아야 해서 의문점 |
| 볼륨 | CoreAudio 기본 출력 장치의 가상 주 볼륨(안 되면 채널별 볼륨), 음소거 속성. 보는 동안 1초마다 읽어 바뀜을 안다 | 공개 API |
| 권한 | 처음 AppleScript 를 보낼 때 macOS 가 앱마다 "자동화" 허락을 묻는다(Info.plist 에 `NSAppleEventsUsageDescription`). 거절하면 설정 창에 이유 | |

윈도우
| 할 일 | 방법 | 비고 |
|---|---|---|
| 재생 정보 | `Windows.Media.Control` 의 `GlobalSystemMediaTransportControlsSessionManager`(윈도우 10 1809 이상). 지금 세션의 곡 정보, 재생 상태, 시간 정보 | 시스템 미디어 컨트롤에 붙는 모든 플레이어(Spotify, 브라우저, 미디어 플레이어) |
| 바뀜 알기 | 세션 바뀜, 곡 정보 바뀜, 재생 상태 바뀜, 시간 바뀜 이벤트 | |
| 조작 | `TryTogglePlayPauseAsync`, `TrySkipNextAsync`, `TrySkipPreviousAsync`. 플레이어가 막은 조작은 버튼을 흐리게(재생 정보의 컨트롤 허용 값) | |
| 앨범 그림 | 곡 정보의 `Thumbnail` 스트림에서 바이트를 읽는다 | |
| 볼륨 | Core Audio `IAudioEndpointVolume`(기본 출력 장치), 바뀜 알림 등록 | 공개 COM API |
| 의존 | WinRT 를 부르려면 `windows` 크레이트가 필요하다(지금은 `windows-sys` 만). 순수 Rust 바인딩이라 C 컴파일러는 필요 없다 | 패키지 없는(MSIX 아닌) 데스크톱 앱에서 세션 관리자를 부를 수 있는지는 문서로 확인 못 함. 구현 첫 단계에서 CI 로 확인 |

## 앨범 그림

- 한 변 최대 320px, JPEG 품질 80 으로 줄여 보낸다(대략 20~40KB). 줄이기와 다시 담기는 운영체제 기능으로: 맥 ImageIO, 윈도우 WIC. 새 이미지 라이브러리를 들이지 않는다
- 연결 메시지 하나의 상한이 65535 바이트(`core/src/wire.rs` `MAX_BODY`)이다. 줄인 그림이 60KB 를 넘으면 품질을 낮춰 다시 담고, 그래도 넘으면 그림 없이 보낸다
- 그림마다 해시를 붙여, 폰이 이미 가진 그림이면 다시 보내지 않는다. 폰은 마지막 몇 장만 기억한다
- 곡 정보와 그림은 따로 보낸다. 곡을 먼저, 그림을 뒤에 보낸다. 블루투스에서는 그림을 다른 값과 따로 보내고, 보내는 시간을 재 보고 너무 느리면 블루투스일 때 그림 상한을 낮춘다

## 하지 않는 것

- 위치 옮기기(진행 바 끌기), 재생 목록, 셔플, 반복, 좋아요
- 맥의 음악 앱, Spotify 밖 플레이어(브라우저 영상 등)
- 가사
- 출력 장치 바꾸기

## 경계 상황

| 상황 | 동작 |
|---|---|
| 재생 중인 것이 없음 | "재생 중인 곡 없음", 버튼 흐리게. 볼륨은 그대로 보임 |
| 플레이어가 둘 이상 | 맥: 재생 중인 쪽, 둘 다 멈춤이면 마지막에 바뀐 쪽. 윈도우: 운영체제가 정한 지금 세션 |
| 재생 중 플레이어를 끔 | 세션 없음으로 바뀌고 위 줄과 같다 |
| 전체 길이를 모름(라디오, 생방송) | 진행 바를 숨기고 지난 시간만 |
| 광고, 그림 없는 곡 | 기본 그림(시안의 바다 그림 자리)과 제목만 |
| 그림이 크거나 깨짐 | 줄이기 실패면 그림 없이 |
| 맥 자동화 권한 거절 | 그 앱만 정보 없음, 설정 창에 "음악 앱 제어를 허용해 주세요" |
| 볼륨 조절 불가 장치 | 볼륨 막대를 숨기거나 흐리게 |
| 이어폰을 꽂아 출력 장치가 바뀜 | 기본 장치를 다시 찾아 감시를 옮기고 볼륨을 다시 보낸다 |
| 폰에서 볼륨 막대를 끌 때 | 끄는 동안 폰은 0.1초 간격으로 마지막 값만 보낸다. 컴퓨터는 최신 값만 적용 |
| 컴퓨터에서 볼륨을 바꿈 | 폰 막대가 따라 움직인다. 폰이 끄는 중이면 손을 뗄 때까지 무시 |
| 명령 직후 끊김 | 명령 번호로 두 번 실행 막기. 재생/멈춤은 뒤집기라 특히 중요 |
| 아무도 안 봄 | 감시(분산 알림, WinRT 이벤트, 볼륨 감시)를 끊는다(설계 5절) |

## 조치

- 메시지(곡, 재생 상태, 그림, 볼륨, 조작 명령)는 공용 코어 Protobuf 에 더한다. 모르는 값은 무시
- 구독과 보내기 규칙, 그림 해시 기억은 `desktop/domain`, 운영체제 포트(`Player`, `Volume` 같은 이름)는 `desktop/mac`, `desktop/windows`
- 안드로이드 Jetpack Compose, iOS SwiftUI, 시안 그대로

## 끝난 기준

- [ ] 맥 음악 앱과 Spotify 에서 곡을 틀면 폰에 그림(Spotify 는 의문점 결정대로), 제목, 진행이 나오고 진행 바가 스스로 움직인다
- [ ] 폰에서 재생/멈춤, 이전, 다음을 누르면 컴퓨터가 따른다
- [ ] 폰과 컴퓨터 어느 쪽에서 볼륨을 바꿔도 서로 맞는다
- [ ] 아무도 음악을 안 보면 감시가 멈춘다(시험)
- [ ] 그림이 60KB 를 넘지 않고, 같은 그림은 다시 보내지 않는다(시험)
- [ ] 윈도우용 컴파일 검사를 통과한다(윈도우 플레이어, 볼륨과 CI 시험은 별도 작업, win)
- [ ] 안드로이드 화면이 시안대로 나온다(iOS 는 별도 작업)

## 의문점 후보 (tickets/의문점.md 27~31 로 옮김)

1. 맥 시스템 전체 "지금 재생 중": 공개 API 가 없다. 비공개 MediaRemote 는 15.4 부터 막혔고, `/usr/bin/perl` 로 우회해 읽는 오픈소스(mediaremote-adapter)가 있으나 비공개 API 우회다. 기본값: 쓰지 않고 앱별 AppleScript(음악 앱, Spotify)만
2. Spotify 앨범 그림: AppleScript 는 인터넷 주소만 준다. 설계 6절은 인터넷을 기상청(과 날씨)만 쓴다고 정했다. 기본값: 내려받지 않고 기본 그림
3. 윈도우 WinRT 를 위해 `windows` 크레이트를 새로 들일지(대안은 COM 을 손으로 부르기, 훨씬 길다). 기본값: 들인다
4. 맥 다른 플레이어(브라우저의 유튜브 등)는 미디어 키(`CGEventPost` 시스템 정의 이벤트, 손쉬운 사용 권한)로 조작만 하고 정보는 없이 둘지. 기본값: 이번에는 안 함

확인한 것(2026-11-27 웹 검색)
- MediaRemote: macOS 15.4 에서 `mediaremoted` 가 권한(entitlement) 검사를 더해 서드파티가 재생 정보를 못 받게 됐다는 보고가 여럿(BetterTouchTool 릴리스 노트, media-remote 크레이트 문서). 애플 공식 발표는 못 찾음
- 음악 앱 AppleScript: 현재 곡 그림 `raw data` 읽기는 Big Sur 11.3 에서 고쳐졌다. macOS 26 에서 자동 재생 곡의 `current track` 이 -1728 오류를 낸다는 보고가 있다(애플 개발자 포럼)
- Spotify AppleScript: `artwork url of current track` 으로 주소를 준다
- 윈도우 `GlobalSystemMediaTransportControlsSessionManager`: 윈도우 10 1809 이상, `TryGetMediaPropertiesAsync` 의 `Thumbnail` 은 스트림 참조. 공식 문서에 `globalMediaControl` 능력이 적혀 있는데 패키지 없는 데스크톱 앱에 필요한지는 확인 못 함
- 맥 "자동화" 권한 묻기는 이번 검색 결과에 없어 내 지식 기준이다
