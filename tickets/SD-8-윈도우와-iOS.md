# SD-8 [공통] 윈도우와 iOS 따라잡기, CI

| 종류 | 상태 | 우선순위 | 라벨 |
|---|---|---|---|
| 작업 | 진행 중 | 높음 | Desktop, iOS, CI |

## 목적

윈도우와 iOS 를 맥, 안드로이드와 같은 수준으로 끝까지 맞춘다. 윈도우 실제 동작은 GitHub Actions 윈도우 서버에서 확인하고(설계 10절 5단계), 네 플랫폼의 빌드와 시험을 푸시마다 자동으로 돌린다.

## 윈도우

범위
- 성능: CPU, GPU, 메모리, 시스템 디스크 사용률, 네트워크 받기/보내기 속도. 맥과 같은 셈(앞 값과의 차이, 오래 쉬었으면 짧게 두 번 재기)
- 프로세스: 목록(이름, CPU %, 메모리, 시작 시각), 종료는 번호와 시작 시각이 둘 다 맞을 때만
- 기기 이름
- 날씨: HTTP 받기는 운영체제 기능(WinHTTP)으로. 새 TLS 라이브러리를 들이지 않는다
- 기상청 인증키: 자격 증명 관리자에 둔다
- USB: 안드로이드는 맥과 같은 adb 서버 방식(이미 공용 코드)
- USB: 아이폰은 애플 장치 서비스의 usbmuxd(127.0.0.1:27015)에 접속해 맥과 같은 공용 usbmux 링크로 붙는다. 컴퓨터에 포트를 열지 않는다
- 설정 창: 맥과 같은 창이 윈도우(WebView2)에서도 뜬다

하지 않는 것
- 윈도우 블루투스. 윈도우에는 BLE L2CAP 채널을 여는 공개 API 가 없다(확인한 범위). 설정 창에는 "윈도우에서는 블루투스를 아직 지원하지 않습니다"
- 설치 파일, 시작 프로그램 등록, 트레이 아이콘(배포 티켓)

## iOS

범위
- 연결: 안드로이드와 같은 규칙(짝 맺기, Ready 뒤 이어받기, USB 우선, 끊기면 마지막 값 흐리게, 다시 붙기)
  - USB: 아이폰 앱이 기기 안 127.0.0.1 의 정해진 포트에서 기다리고, 맥이 usbmuxd(`/var/run/usbmuxd`, 공개 프로토콜)를 거쳐 그 포트에 붙는다. 맥에는 포트를 열지 않는다
  - 블루투스: 안드로이드와 같은 BLE L2CAP. 아이폰은 알림 신호에 서비스 데이터를 실을 수 없어서(iOS 제약), PSM 과 알림 신호 지문을 읽기 전용 GATT 특성 하나에 두고 맥이 붙을 때 읽는다
- 화면(SwiftUI): 홈 시계 다섯 모양(숫자, 바늘, 날씨, 달력, 모아 보기)과 라이트, 다크 테마, 성능, 프로세스(정렬, 끝내기), 작은 칸, 옆으로 밀기와 길게 누르기, 위치 권한 안내, 날씨 출처, 끊기면 흐리게, 짝 맺기 숫자 확인
- 확인 창은 공통 확인 창(`ConfirmModal`) 하나로
- 아이폰 세로와 가로. 테마와 시계 모양은 기기에 저장한다

하지 않는 것
- 실제 아이폰에서 돌려 보기(기기와 애플 개발자 계정이 없음). 시뮬레이터까지만
- usbmux 실제 연결 확인. 기기 없이는 할 수 없어 가짜 소켓으로 프로토콜만 시험한다
- 블루투스로 처음 등록하기(안드로이드와 같이 USB 로만)
- 쉴 때 검은 화면, 진동, 화면 안 꺼짐(다음 티켓)
- 아이패드 전용 배치

## iOS 조치

- 연결 규칙은 안드로이드 `LinkOwner`, `Connection` 을 Swift 로 옮긴다. 아이폰 USB 는 adb 처럼 접속한 쪽을 확인할 방법이 없으므로, USB 도 Noise 가 상대를 확인한 뒤(짝 맺기 숫자 또는 Ready)에 이어받는다
- usbmux 링크는 공용 `desktop/link` 에 두고 usbmuxd 에 접속하는 부분만 운영체제별로 갈아 끼운다(맥 유닉스 소켓). 안드로이드 USB 와 같은 USB 길로 다룬다. 한 길에 링크가 둘이 되어도 설정 창의 기기 목록이 서로 덮지 않게 `desktop/domain` 이 목록을 합친다
- 맥 블루투스는 서비스 데이터가 없는 SideDesk 알림 신호면 한 번 붙어 GATT 특성을 읽고 끊은 뒤 지금처럼 등록 여부를 본다
- 시뮬레이터에서는 USB 대기를 열지 않는다(시뮬레이터의 127.0.0.1 은 맥의 것이라 맥에 포트가 열린다). 화면 확인은 디버그 빌드 전용 보기용 값으로 한다
- 시험과 화면 찍기는 GitHub Actions macOS 서버의 시뮬레이터에서 돌리고 화면은 산출물로 올린다. 이 맥에는 시뮬레이터 런타임을 받지 않는다
- 화면은 SwiftUI, MVVM. 색과 크기는 안드로이드 `Palette` 와 시안을 따른다

## iOS 끝난 기준

- [ ] 시뮬레이터에서 홈 다섯 모양, 성능, 프로세스 화면이 세로, 가로, 라이트, 다크로 겹침 없이 나온다(화면 찍기)
- [ ] 길게 눌러 모양과 테마를 고르고, 앱을 다시 켜도 남는다
- [ ] 프로세스를 누르면 공통 확인 창이 뜨고, 끝내기를 누르면 컴퓨터로 명령이 간다(시험)
- [ ] 연결 규칙(Ready 뒤 이어받기, USB 우선, 다른 컴퓨터 거절, 끊기면 흐리게) 단위 시험이 통과한다
- [ ] 맥 usbmux 링크가 가짜 usbmuxd 로 기기 목록, 붙기, 거절 이유를 맞게 낸다(시험)
- [ ] 위치 권한을 주면 날씨를 받고, 주지 않으면 --° 가 나온다
- [ ] 실제 아이폰 USB, 블루투스 연결은 기기가 생기면 확인한다(지금은 없음)

## CI

범위
- `.github/workflows/ci.yml` 하나, 푸시와 PR 마다
- macOS: `cargo clippy`, `cargo test`
- windows-latest: `cargo clippy`, `cargo test`, 윈도우 전용 시험(자격 증명 관리자, 인터넷 받기, 설정 창 띄우기), 윈도우 실행 파일 빌드
- 안드로이드(macOS 서버): `./gradlew testDebugUnitTest assembleDebug`
- iOS(macOS 서버): 시뮬레이터 빌드와 시험
- 비밀값을 쓰지 않는다

## 조치

- 윈도우 수집과 실행은 `desktop/windows`, Win32 공개 API(`windows-sys`)만 쓴다
- 앱의 윈도우 분기(`desktop/app`)에서 날씨와 키 보관을 맥과 같게 잇는다
- 설정 창의 WebView2 자료 폴더를 설정 폴더(`%APPDATA%\SideDesk`) 안으로 옮긴다

## 끝난 기준

- [ ] 윈도우 서버 CI 에서 자격 증명 관리자 넣기/읽기/지우기와 인터넷 받기 시험이 통과한다
- [ ] 윈도우 서버 CI 에서 설정 창이 열리고 화면이 읽힌다
- [ ] 윈도우 앱이 아이폰 usbmux 링크를 127.0.0.1:27015 로 잇고, 접속 시험이 통과한다(실제 아이폰 연결은 기기와 윈도우 PC 가 있으면 확인)
- [ ] 네 작업(macOS, 윈도우, 안드로이드, iOS)이 CI 에서 모두 통과한다
- [ ] 실제 윈도우 PC 에서 폰과 붙는지는 PC 가 있으면 확인한다(지금은 없음)
