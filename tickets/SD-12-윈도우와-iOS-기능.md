# SD-12 [공통] 윈도우와 iOS 에 남은 기능 붙이기

| 종류 | 상태 | 우선순위 | 라벨 |
|---|---|---|---|
| 작업 | 진행 중 | 높음 | Desktop, iOS, CI |

## 목적

맥과 안드로이드에 들어간 AI 세션(SD-7), 단축키(SD-9), 음악(SD-10), 쉴 때 화면(SD-11)과 상주(SD-14)를 윈도우와 iOS 에도 같은 수준으로 붙인다. 윈도우 실제 동작은 GitHub Actions 윈도우 서버에서 확인한다.

## 윈도우

범위
- 단축키 실행기
  - 앱 열기: 시작 메뉴의 앱(일반 앱과 스토어 앱 모두, `shell:AppsFolder`)을 목록으로 고르고 연다
  - 파일, 폴더 열기: 파일 고르기 창으로 고르고 기본 앱으로 연다
  - 주소 열기: 기본 브라우저(http, https 만)
  - 키 조합: `SendInput`. 앞에 있는 창에 보낸다
  - 소리 끄기/켜기: 기본 출력 장치 음소거, 상태를 폰 버튼에 보임
  - 화면 잠금: `LockWorkStation`
  - 방해 금지: 공개 API 가 없어 윈도우에서는 고를 수 없게 숨긴다
- 음악: 시스템 미디어(시스템 미디어 컨트롤에 붙는 모든 플레이어)의 곡, 재생 상태, 앨범 그림, 재생/멈춤, 이전, 다음. 기본 출력 장치 볼륨 읽기와 바꾸기
- AI 세션: 윈도우의 Claude Code, Codex 기록(`%USERPROFILE%\.claude`, `%USERPROFILE%\.codex`)과 `gh`, `glab` 수
- 상주: 시스템 트레이 아이콘. 설정 창을 닫아도 연결은 유지하고, 트레이 메뉴로 창을 다시 열거나 끝낸다(맥 메뉴 막대와 같은 구조, SD-14)

하지 않는 것
- 윈도우 블루투스(SD-8 과 같음)
- 방해 금지(공개 API 없음)
- 로그인할 때 저절로 켜기, 설치 파일(배포 티켓)
- 관리자 권한 창에 키 보내기(윈도우가 막고, 막혔는지 알 방법이 없다)
- 시스템 미디어 컨트롤에 붙지 않는 플레이어의 곡 정보

## iOS

범위(기준은 develop 의 안드로이드 화면과 규칙)
- AI 세션: 큰 화면(세션 카드, GitHub/GitLab 고르기와 숫자 셋), 작은 칸("AI n 작업 중"), 알림(작은 칸이 커지며 4초, 큰 화면 카드 빛남, 화면은 넘기지 않음)
- 진동: Core Haptics. 끝남 한 번, 답변 대기 두 번, 버튼 누름 짧게. 세기는 끔, 약하게, 보통, 강하게
- 단축키: 큰 화면 격자와 작은 칸(앞 네 개), 누르면 진동과 번호만 보냄, 실패만 한 줄
- 음악: 큰 화면(그림, 제목, 진행 바, 이전, 재생/멈춤, 다음, 볼륨), 작은 칸(재생 버튼, 제목, 진행 줄)
- 쉴 때 화면: 손 안 댄 뒤(1분, 5분, 15분, 안 함) 검은 판에 시계만 어둡게, 1분마다 자리 옮김, 누르면 깸. 화면 켜 두기(늘, 충전 중, 안 함)는 앱이 앞에 있을 때만
- 작은 칸 다섯 배치(세로는 위 셋 아래 둘), 화면 차례 홈, AI, 성능, 프로세스, 단축키, 음악
- 최적화(SD-14 원칙): 시각은 쓰는 칸 안에서 분 단위로 읽기, 물결은 값이 바뀔 때만 움직이기, 쉬는 동안 아래 화면 멈추기

하지 않는 것(iOS)
- 실제 아이폰 확인(기기 없음), 진동 세기를 몸으로 확인하기
- 쉬는 동안 화면 밝기 낮추기. iOS 의 화면 밝기는 시스템 밝기라 바꾸면 앱 밖에도 남는다. 검은 판으로만 어둡게 한다
- 폰에서 단축키 등록, 음악 진행 바 끌기, AI 세션에 답하기

## 조치(iOS)

- core 는 고치지 않는다. 새 일과 명령은 develop 에 이미 있다
- 연결 규칙(단축키와 곡은 보낸 컴퓨터에만, 다른 컴퓨터가 붙으면 지움, 볼륨은 마지막 값 하나, 알림은 한 번)은 안드로이드 `LinkOwner` 를 그대로 옮긴다
- 화면은 SwiftUI, MVVM. 시험과 화면 찍기는 CI 시뮬레이터에서

## 끝난 기준(iOS)

- [ ] AI, 단축키, 음악 큰 화면과 작은 칸 다섯 배치, 쉬는 화면이 시뮬레이터에서 세로, 가로, 라이트, 다크로 겹침 없이 나온다(화면 찍기)
- [ ] 연결 규칙과 화면 모델(알림, 단축키, 음악 진행과 볼륨, 쉼과 켜 두기) 단위 시험이 CI 에서 통과한다
- [ ] 값이 바뀌지 않는 동안 매 프레임 그리기가 없다(물결과 1초 타이머 없음, 코드와 시험으로)
- [ ] 실제 아이폰 진동, 화면 켜 두기는 기기가 생기면 확인한다(지금은 없음)

## 조치(윈도우)

- `desktop/windows` 에 실행기, 음악, 볼륨, 그림 줄이기를 채운다. COM 과 WinRT 는 `windows` 크레이트로 부른다(C 컴파일러 없이 빌드됨)
- `desktop/app` 의 윈도우 분기에서 AI 세션과 gh/glab 을 잇는다
- 트레이는 be 의 SD-14 구조를 따른다

## 끝난 기준(윈도우)

- [x] 윈도우 서버 CI 에서 앱 목록 읽기, 키 조합 보내기, 음소거 읽기(장치가 있으면 바꾸고 되돌리기) 시험이 통과한다 (실행 45884472108. 앱 174개. 서버에 소리 장치가 없어 음소거와 볼륨은 "장치 없음" 길만 확인)
- [x] 윈도우에서 실행 파일(exe, bat, ps1, lnk, hta 등과 PATHEXT), 네트워크 경로, 대체 데이터 스트림은 파일 열기로 등록도 실행도 되지 않고, 앱 열기는 지금 앱 목록에 있는 것만 연다(시험)
- [ ] 윈도우 설정 창에서 방해 금지를 고를 수 없고, 폴더 고르기 버튼이 따로 있고, 키 조합이 Ctrl, Alt, Shift, Win 글자로 보인다(스냅숏 값은 시험으로 확인, 화면 모양은 윈도우 PC 가 없어 못 봄)
- [x] 콘솔 명령(`sidedesk-cli pair`, `run`)이 터미널에서 돌고, 모르는 인자면 종료 코드 1 과 사용법이 나온다(윈도우 CI, 실행 45884472108)
- [x] 트레이에서 창을 닫았다가 다시 열 수 있고 같은 WebView2 자료 폴더를 쓴다(윈도우 CI, 실행 45884472108. 두 번 열고 읽기까지 0.8초)
- [x] 윈도우 서버 CI 에서 시스템 미디어 세션 관리자를 패키지 없는 앱에서 열 수 있고, 재생 중인 것이 없으면 "없음"이 나온다(실행 45884472108)
- [x] 윈도우 서버 CI 에서 그림 줄이기가 60KB(블루투스 24KB) 안의 JPEG 를 만든다(실행 45884472108. 1200x900 시험 그림이 17KB)
- [x] 윈도우 서버 CI 에서 AI 세션 읽기와 gh 실행 시험이 통과한다(실행 45884472108. gh 실행기는 cmd 와 손자 ping 으로 시험)
- [x] 윈도우 서버 CI 에서 트레이 아이콘을 만들고 지울 수 있다(실행 45884472108)
- [x] 네 작업(macOS, 윈도우, 안드로이드, iOS)이 CI 에서 모두 통과한다(실행 45884472108, 24e736f)
- [ ] 실제 윈도우 PC 에서 폰과 붙여 보는 것은 PC 가 있으면 확인한다(지금은 없음)
