# SD-1 [공통] 뼈대

| 종류 | 상태 | 우선순위 | 라벨 |
|---|---|---|---|
| 작업 | 진행 중 | 높음 | Core, Desktop, Android, iOS |

## 목적

컴퓨터 프로그램, 안드로이드 앱, iOS 앱이 처음부터 끝까지 얇게 이어진 뼈대를 만든다. 이후 기능은 이 뼈대에 하나씩 붙인다.

## 범위

- 컴퓨터 프로그램을 헥사고날로 나눈다. 기능 코드는 운영체제와 연결 방법을 모른다
- 안드로이드 앱과 iOS 앱의 빈 틀을 MVVM 으로 만든다
- 공용 코어(Rust)를 두 앱과 컴퓨터 프로그램이 같이 쓴다
- 컴퓨터 이름 하나를 폰으로 보내 화면에 보인다

하지 않는 것
- 암호화, 짝 맺기, 다시 연결하기 (SD-2)
- 홈을 비롯한 실제 기능 화면 (SD-3 부터)
- 트레이, 설정 창, 설치 파일
- 윈도우에서 실제로 실행해 보기. 컴파일 검사까지만 한다

## 조치

- 컴퓨터 프로그램은 다섯 크레이트로 나눈다

| 크레이트 | 맡는 일 | 쓰는 크레이트 |
|---|---|---|
| `domain` | 기능, 바깥에 요구하는 약속(포트) | `core` |
| `mac` | 맥에서 값을 읽고 실행 | `domain` |
| `windows` | 윈도우에서 값을 읽고 실행 | `domain` |
| `link` | 폰과 연결 | `domain` |
| `app` | 시작점. 위의 것을 골라 이어 준다 | 전부 |

- 포트는 바깥으로 나가는 것만 둔다. 기능은 함수로 바로 부른다
- 폰 앱은 화면, 화면에 보일 값, 연결 세 부분으로 나눈다
- 이번 연결은 암호화가 없다. 개발용 빌드에만 넣고 배포용 빌드에는 들어가지 않게 한다. SD-2 에서 지운다
- 컴퓨터에는 포트를 열지 않는다

## 끝난 기준

- [x] `domain` 이 `mac`, `windows`, `link` 를 쓰면 빌드가 실패한다
- [x] 가짜 구현을 넣어 `domain` 만 시험할 수 있다
- [x] 맥에서 보낸 컴퓨터 이름이 안드로이드 폰 화면에 나온다
- [ ] 맥에서 보낸 컴퓨터 이름이 iOS 시뮬레이터 화면에 나온다
- [x] 폰이 없거나 앱이 꺼져 있어도 컴퓨터 프로그램이 죽지 않고 이유를 알린다
- [x] 배포용 빌드에는 개발용 연결이 없다
- [x] 윈도우용 컴파일 검사를 통과한다
